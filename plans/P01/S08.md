## Root causes and decisions

- The Polar sunrise/sunset failure was an unconditional `.astimezone()` on optional astral results. The implementation uses a daytime fallback and additionally handles a single missing event, naive/inconsistent events, and Home Assistant's configured timezone.
- Best-condition selection compared only `local_time.day` with `date.today().day + 1`; this both used the host calendar and could never match day 32 at month end. Exact local-date equality selects only current-day candidates regardless of month/year boundaries or source ordering.
- FMI value wrappers are typed as floats, but external payloads can still be malformed at runtime. One shared finite-number boundary accepts numeric strings and rejects booleans, malformed strings, `None`, NaN, and infinity.
- Unknown symbols map to no condition rather than a false weather state. Only clear symbol `1` gets the documented sun-event transformation.
- The time audit confirmed naive request construction and string timestamps in lightning/sea-level code. S09 already owns their age semantics and parser contract, so S08 records the evidence without a partial incompatible change.
