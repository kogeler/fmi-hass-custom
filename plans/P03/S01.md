## Objective

translated empty state, transition logging, and recovery while retaining the old non-empty address
presentation until S02.

## Baseline and evidence

- Production passed `bool` as the lightning source predicate, so `[]` and `None` both marked the
  source unavailable.
- The lightning entity used `if not data`, collapsing empty and failed data to `native_value=None`.
- Existing failure tests proved primary-source isolation but did not assert the public lightning
  state or the empty/failure/recovery transition sequence.

## Changes made

- Lightning source success now means `data is not None`; an empty list remains available.
- `FMILightningStrikesSensor` publishes `no_strikes` for successful empty data and directly checks
  the coordinator's lightning source flag in addition to inherited availability.
- Empty and failure updates replace the entire dynamic attribute mapping; failure keeps native
  value `None` and public state unavailable.
- Added English and Finnish state translations and HA/coordinator regressions covering startup
  empty, non-empty, failure, stale clearing, repeated failure, recovery, and replacement.
- Updated availability contracts with the final tri-state behavior.
