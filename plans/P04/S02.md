## Objective

Expose feels-like temperature, dew point, atmospheric pressure, three cloud layers, precipitation
probability, and thunderstorm probability as ordinary Home Assistant sensors, then add apparent
temperature and hourly PoP through Home Assistant's standard weather API.

## Changes made

- Added the eight frozen sensor descriptions to the existing unified sensor setup/update path.
  They retain the same selected current/configured-interval timestamp policy, location device,
  entity naming, finite-value handling, attribution, and availability behavior as sibling sensors.
- Added temperature/pressure device classes and native units, percentage state contracts, frozen
  icons, and English/Finnish translations.
- Reused cached client fields for feels-like, dew point, pressure, and cloud layers. Probability
  sensors read the S01 coordinator supplement at the selected source timestamp and perform no I/O.
- Retained explicit `0.0` and `100.0`; missing or invalid per-field data affects only that entity
  and later valid data recovers the same registry record without reload.
- Added current apparent temperature for forecast-backed and configured-station weather when the
  client supplies a finite value.
- Added hourly apparent temperature and validated integer PoP using the frozen half-to-even rule.
  Daily forecast exposes maximum finite apparent temperature and contains no PoP field.
- Extended only synthetic fixtures/builders; no live or private payload was captured.
- Updated sensor, forecast, availability, runtime, and translation contracts.
- Kept migration verification cohesive: it asserts one complete post-setup registry unique-ID set
  and preserved historical registry IDs, without parallel legacy/new implementation paths.

## Contract evidence

- Home Assistant state tests cover all eight values, units, stable suffixes, device ownership,
  explicit probability boundaries, per-field missing data, and supplement recovery.
- Configured-interval regression proves a probability sensor looks up the same timestamp selected
  by the common sensor policy.
- Public weather state/service tests cover main and station apparent temperature, hourly PoP,
  maximum daily apparent temperature, and absence of daily PoP.
- US customary tests prove sensor temperature and pressure conversion plus current/hourly/daily
  apparent-temperature conversion. Home Assistant intentionally serializes weather temperatures
  at its whole-degree display precision while numeric sensor state retains its own precision.
- Migration tests prove all historical registry IDs/unique IDs remain and the complete requested
  metric identity set is added to each existing entry.
