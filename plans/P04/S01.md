## Objective

Generalize the existing bounded gust adapter so the same FMI response supplies timestamp-aligned
PoP and thunder probabilities, with immutable typed ownership and stale-data clearing before any
new entity exposes them.

## Baseline and evidence

- The locked client omits `PoP` and `ProbabilityThunderstorm` and cannot store them in its fixed
  `WeatherData` NamedTuple.
- The existing production adapter already edits the one coordinate request and safely parses
  `HourlyMaximumGust` by response field name and aware UTC timestamp.
- S00 official metadata proved both new parameter names exist in the same selected product.
- The pre-change live baseline was four passing probes and 7/12 request attempts.

## Changes made

- Added `HourlyMaximumGust`, `PoP`, and `ProbabilityThunderstorm` exactly once to the existing
  parameter list.
- Generalized the single bounded XML pass to extract all three fields by response name, independent
  of column order.
- Added immutable `ForecastProbabilities`, `CurrentWeatherResult`, and `ForecastResult`; future
  values cross the adapter boundary in a `MappingProxyType` keyed by aware UTC datetime.
- Preserved upstream `WeatherData`; gust normalization remains unchanged.
- Added finite 0–100 validation without clamp or zero substitution. Valid `0.0` and `100.0` remain
  data. Invalid optional rows/timestamps are skipped without poisoning mandatory upstream weather.
- Retained last-row-wins duplicate timestamp semantics.
- Added one typed coordinator supplement state. Current/forecast replacement, empty results,
  failures, and primary timeout clear their owning probability values; recovery needs no reload.
- Updated config-flow consumption for the typed current result without changing its place outcome.
- Extended live assertions through the production adapter for current Helsinki, current-day hourly
  Helsinki, and current-day hourly Kilpisjärvi while retaining the same test count and budget.
- Updated current sensor-adapter, runtime, and live-test maintenance contracts.
