## Objective

Replace visible raw coordinates in setup and reconfiguration with Home Assistant's standard map
selector while preserving the established storage, duplicate, identity, and reload contracts.

## Baseline and evidence

S00 established that the HA 2026.8.1 selector needs integration-owned finite WGS84 validation.
Existing tests characterized top-level stored coordinates, pre-write validation, random fresh
identity, in-place reconfigure, migration, and registry preservation.

## Changes made

- Added a standard `LocationSelector` subclass that retains selector type `location` and rejects
  missing, boolean, non-finite, and out-of-range coordinates before FMI I/O.
- Added one flattening boundary from transient `location` mapping to the existing top-level stored
  latitude/longitude fields.
- Made setup default the marker to Home Assistant's configured location and reconfigure default it
  to the entry's stored location.
- Preserved `name`, immutable identity, unique ID, options, entry version, and registry behavior;
  `location` is never persisted.
- Added the previously missing second duplicate check to reconfiguration, matching initial setup's
  concurrent-flow protection.
- Replaced raw-coordinate strings with a translated map step, updated the current reconfiguration
  contract, and added the notable change to the existing `1.1.0` changelog section.
- Updated all config-flow/migration/privacy callers to exercise the new public selector shape.

## Decisions

No new decision was required. D005, D010, and D011 directly governed the implementation. The place
menu stayed unexposed until S02 can deliver the complete alternative path.
