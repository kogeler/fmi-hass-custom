## Objective

## Baseline and evidence

The complete verified inventory, state diagrams, error classifications, request-budget decision,
and references are in `plans/P02/BASELINE.md`. Local source inspection used the locked Home
Assistant 2026.8.1 and `fmi-weather-client` 1.0.0 toolbox, not assumptions from the earlier plan.

The key discrepancy found was that Home Assistant's standard location selector coerces floats but
does not itself reject booleans, non-finite values, or geographic-range violations. The plan was
corrected to require integration-owned candidate validation while retaining the standard selector
UI. The selected FMI public async place method was confirmed to dispatch through an executor and
return the already-supported `Weather` model shape.

S02 review later corrected an incomplete S00 inference: the async convenience method parses before
the integration can apply its existing XML size boundary. `BASELINE.md`, the S02 work item, and
D013 now require the same selected request/timeout/parser semantics with bounded pre-validation;
the signature/executor characterization remains evidence about the dependency, not authorization
to bypass the security contract.
