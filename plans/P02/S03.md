## Baseline and evidence

The S02 flow already performed duplicate checks before and after final external validation. A new
genuinely overlapping same-point test was added before considering extra locking. Home Assistant
created one entry and the second flow observed it at the existing post-validation check, so no
production synchronization mechanism was justified. A separate concurrent distinct-point test
proved that transient candidates and generated identities remain independent.

The live suite retained exactly four collected tests. Its southern dependency probe was replaced
with public Helsinki name resolution followed by normal resolved-coordinate validation. This
changed the measured nominal request count from six to seven and the bounded retry ceiling from ten
to twelve while retaining two-request concurrency.

## Plan corrections and investigated deviations

- The plan's baseline sentence still described the old ten-attempt limit as if current. It now
  states explicitly that ten is pre-P02 evidence and D012 raises only the S03 counter to twelve.
- An extra production lock was considered only after adding a real overlap test. The test proved
  the current pre/post duplicate boundary atomic for the supported HA flow manager, so adding state
  or locking would have been unsupported complexity.
- The isolation test initially called setup on a second entry that HA had already loaded while
  setting up the first domain entry. It was corrected to follow the public `ConfigEntryState`, as
  existing migration helpers already do; no runtime behavior was changed.

## Decisions
