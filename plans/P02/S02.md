## Objective

Expose complete map and FMI place-name paths for both setup and reconfiguration, require explicit
map confirmation of search results, and route every final point through the existing validation
and persistence boundary.

## Baseline and evidence

The locked client provides a place query with the same WFS endpoint, ten-second timeout, forecast
parser, and executor-backed convenience API. During implementation review, direct use of that
convenience wrapper was found to parse before the integration could enforce its established 2 MiB
XML ceiling. The plan and baseline were corrected before retaining that design.

Home Assistant's flow manager also proved that menu options are schema-validated and that there is
no backend previous-step callback. Frontend Back/close is therefore represented by aborting the
uncommitted flow and starting a new independent path.

## Changes made

- Made `user` and `reconfigure` translated menus with exactly `map` and `place` options.
- Added a translated text-selector search step and `place_confirm` map with canonical result text.
- Added an immutable `PlaceResolution` adapter result and a synchronous selected-client request /
  bounded XML pre-validation / selected parser pipeline executed through `asyncio.to_thread`.
- Reused the dependency's ten-second timeout and privacy-filtered logging while rejecting unsafe,
  oversized, empty, non-finite, boolean, and out-of-WGS84 results before flow state.
- Kept setup display `name` separate from transient place text. Neither query nor selector wrapper
  is persisted.
- Unified map and confirmation finalization across setup/reconfigure, including pre/post external
  duplicate checks, translated failure mapping, and final canonical title resolution.
- Added success, adjustment, no-data, client/server/transport/malformed, empty-query, duplicate,
  retry, abort/restart, cancel, and reconfigure coverage.
- Updated current runtime, security/privacy, and reconfiguration contracts plus the existing
  `1.1.0` changelog entry.
- Removed an impossible confirmation-without-candidate recovery branch after HA menu validation
  proved it dead.

## Decisions

- D013: do not call the unbounded async convenience parser directly; insert the existing bounded
  safe-XML boundary while preserving selected-client request/parser semantics.
- D014: prove Back/cancel as non-mutating abort plus fresh-flow isolation because HA exposes no
  backend Back callback.
- Removed an initially added 200-character query limit because neither the plan nor an FMI contract
  justified that arbitrary policy.
