## Objective

Audit the supported Home Assistant environment, dependency graph, workflows, logs, diagnostics, and reverse-geocoder boundary; fix every confirmed critical/high compatibility, security, or privacy issue and record an explicit support matrix.

## Changes made

- Replaced the per-entry nested `hass.data` dictionary with typed `FMIConfigEntry`/`FMIEntryRuntimeData`, and moved sensor/weather setup plus listener cleanup to `ConfigEntry.runtime_data`.
- Added Home Assistant diagnostics that redact latitude, longitude, and coordinate-derived legacy identity while exposing only options, config versions, source health, and polling cadence.
- Removed configured coordinates and raw external text from integration logs; added an idempotent dependency-logger privacy filter for the FMI client's request/place debug and raw parser response records.
- Kept optional lightning bounding boxes within WGS84 at poles and antimeridian crossings.
- Audited current HA quality guidance, stable/beta compatibility, full/runtime dependency graphs, licenses, direct/transitive version drift, workflow/action sources, logs, diagnostics, and reverse geocoding.
- Added the explicit stable-only support matrix, Nominatim private-testing constraint/TODO, S15 nested-image finding, audit report, changelog entries, and current dependency evidence.

## Root causes and decisions

- Current HA guidance makes `ConfigEntry.runtime_data` the consistent typed owner of non-persistent config-entry state. The old dictionary was functional but untyped and duplicated lifecycle identity outside the entry.
- Exact coordinates appeared directly in coordinator debug, external exceptions/bodies were appended to availability warnings, config-flow tracebacks retained chained payload text, and the installed FMI parser logged its decoded dictionary and full XML at error level. Keeping only HTTP/exception classification and filtering the dependency's known sensitive record templates preserves actionable transitions without private data.
- Diagnostics are justified because current quality guidance recommends them and the integration has several independent sources. Returning weather or place payloads was unnecessary; explicit redaction also covers the legacy identity that embeds exact coordinates.
- Stable-only support matches reproduced evidence. No previous-stable lock is retained; beta b2/b3 passing is informational, and the b3 helper mismatch remains visible rather than overridden as a supported graph.
- Stable HA still pins vulnerable Pillow/PyJWT versions exactly. The integration closure is clean and beta uses fixed pins, so the existing owner exception remains formally blocked upstream rather than forcing an inconsistent stable environment.
- Nominatim sees public FMI strike coordinates, not the configured location, and current request/caching/attribution behavior fits owner-only testing. OSMF discourages periodic app use at scale, so broader distribution requires a different provider/removal decision tracked in `TODO.md`.
- Top-level workflow action SHAs and the Python image digest are immutable, but the selected hassfest/HACS actions contain mutable nested images. Read-only permissions and no secrets limit current impact; S15 already owns digest-pinned CI replacement and remote validation.
