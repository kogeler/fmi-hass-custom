## Objective

Add a bounded, marker-isolated live suite that detects FMI client/API drift and proves public forecast and observation data reaches Home Assistant entity state and forecast service output, while keeping all ordinary tests deterministic and offline.

## Changes made

- Replaced the skipped placeholder with dependency-level probes for rounded public Helsinki and Kilpisjarvi forecasts plus Helsinki Kumpula `FMISID 101004` observations.
- Added a full Home Assistant live probe covering config-entry setup, weather/temperature entity state and units, source freshness, hourly/daily forecast services, and local-day precipitation aggregation.
- Added reusable stable contract assertions and an offline malformed-contract diagnostic with exact failure context.
- Documented public identifiers, stored queries, commands, limits, retries/timeouts, assertions, failure classes, CC BY 4.0 attribution, and privacy rules.
- Added an interim live step after the offline tests in the existing `verify.yml` test job, with enforced `-n 0` and no `continue-on-error`; S15 retains ownership of the final CI topology and triggers.

## Root causes and decisions

- Raw dependency success is insufficient because parsing can succeed while Home Assistant entity or service exposure drifts. S12 therefore tests both the installed client boundary and dashboard-facing state/service output.
- The Home Assistant custom-component test helper applies its own per-test DNS/socket guard even when pytest's `--disable-socket` option is removed. The selected live module narrowly restores the captured real socket/DNS methods and reinstates the guard during teardown; offline collection never activates that fixture.
- Owner coordinates and optional lightning/sea-level/geocoding would add privacy and availability noise. Rounded public city/station points cover the required latitude range, while the HA probe suppresses the unrelated sea-level call and bounds real core calls.
- The owner selected a blocking live step in the existing pull-request/default-branch verification job for the S12 interim. Nominal/worst-case request counts remain 6/10, far below current FMI limits; S15 must revisit how upstream outages affect required checks.
