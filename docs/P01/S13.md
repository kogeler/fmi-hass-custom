## Root causes and decisions

- The coordinator caught only FMI `ClientError`/`ServerError`, but the selected synchronous HTTP layer can raise `requests.RequestException`, invalid XML can raise ElementTree/Expat errors, and malformed external shapes can raise a bounded set of conversion/lookup exceptions. Those errors escaped partial-availability logic and let `DataUpdateCoordinator` fail the whole refresh.
- A finite exception tuple at each external await boundary preserves source-local fallback, clearing, transition logs, and recovery without a broad `Exception` catch or cancellation suppression.
- `logging.basicConfig` was inherited module code rather than a Home Assistant logger declaration. Reload instrumentation proved the global call, so removal was sufficient and behavior-neutral for the namespaced logger.
- Coordinate current/forecast requests already used `asyncio.to_thread`; the strengthened contract test now combines Home Assistant `protect_loop` with worker-thread identity assertions. Observation async methods use the installed client's executor, while optional parsing/geocoding uses Home Assistant's executor.
- Repository search found no runtime caller for `get_bounding_box_covering_finland` or its constants. Removing dead code met the assigned behavioral-coverage standard more honestly than a test that merely executed unused lines.
- No new report exists in the canonical fork as of 2026-08-01. Previously inventoried open descriptions remain covered; recent closed descriptions showed no unresolved critical/high regression.
