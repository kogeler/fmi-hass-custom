## Root causes and decisions

- Current Home Assistant prefixes named entities with their device name. The previous weather model supplied both full device and full entity names, producing duplicated observation labels and generated IDs. Main/observation weather now use their device as the primary name and daily weather uses only its sub-entity suffix; stable unique IDs remain unchanged.
- Home Assistant retains registry-backed entities as restored `unavailable` states after unload, but removes them after config-entry removal. Lifecycle assertions now encode both distinct public behaviors.
- The plan incorrectly requested separate observation sensors. Repository history and current code show only an observation-backed weather entity, so S10 item 4 was corrected immediately; adding a new sensor family remains out of scope.
- The aggregate coverage result could hide modules below the final per-module thresholds. S10 met all coverage targets for its owned surfaces; the measured adapter/utility residuals are now explicitly assigned to S13.
