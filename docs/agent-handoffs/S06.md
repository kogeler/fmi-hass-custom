## Objective

Restore correct wind-gust sensor behavior and location-aware entity organization using current Home Assistant sensor, device, naming, identity, and migration contracts while preserving existing customized entity IDs.

## Changes made

- Added a narrow `fmi-weather-client` adapter that adds FMI's `HourlyMaximumGust` to the existing forecast/current WFS request, parses it by timestamp, and normalizes it into the installed client's model without a second request. Observation calls retain their upstream `WindGust` behavior.
- Reworked FMI sensors onto current `SensorEntity`, `CoordinatorEntity`, translated entity descriptions, native values/units, device classes, and state classes. Missing, NaN, and infinite numeric values now make only the affected sensor unavailable; finite zero remains valid.
- Grouped sensors and weather entities under coordinate-identified location devices. Fresh generated IDs now include the resolved FMI place while existing unique IDs remain unchanged.
- Added conservative migration for exact legacy generated sensor IDs. Customized IDs and occupied targets are preserved, and registry entries are renamed in place rather than recreated.
- Added Home Assistant regressions for issues #111/#112, dependency-boundary gust contracts, availability/recovery, multiple locations, Unicode/punctuation, migration safety, and all existing sensor metadata.
- Documented the sensor/gust/naming contracts, updated the dependency boundary record and changelog, and corrected plan assumptions and later-session scope as evidence required.

## Root causes and decisions

- Issue #111 had two interacting causes: the stable client requests forecast `WindGust`, which the selected FMI producer returns as NaN, and the legacy sensor called `math.isnan(None)`, aborting platform setup. FMI publishes `HourlyMaximumGust`, so the integration now requests it in the same call and prefers its finite value, with native `WindGust` only as a fallback. Ordinary wind speed is never substituted.
- Issue #112 came from legacy standalone entity naming without device context. Current Home Assistant naming uses `has_entity_name` plus the device name, so location devices provide fresh location-aware IDs and friendly names without changing stable unique IDs.
- Migration is intentionally exact-match only. Automatically suffixed legacy IDs and multi-entry histories are ambiguous and remain assigned to S11; heuristic renames could overwrite user intent.
- The client adapter deliberately isolates two private upstream calls. Offline request/parser/timestep contracts make upstream drift visible, while avoiding a fork, a vendored dependency, or extra FMI traffic.
- Wind direction remains the existing compass-point string rather than being changed to a numeric direction sensor; that unrelated behavior change requires separate evidence.
