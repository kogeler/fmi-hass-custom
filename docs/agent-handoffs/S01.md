- Replaced all S01 `TBD` commands in `AGENTS.md` and documented the environment, dependency model, layout decision, HACS limitation, and Podman storage warning.
- Reopened S01 before the owner commit to move the plan under `plans/`, replace active flake8 tooling with Ruff, and make Ruff lint/format gates clean as explicitly requested by the owner.

## Root causes and decisions

- The repository owner requires project Python/Home Assistant commands to run through Podman rather than the host Python.
- Current hassfest rejected the root layout with `Domain does not match dir name`; S01 therefore selected the standard `custom_components/fmi/` layout under plan decision D001.
- The first smoke-test collection failed because `async_timeout` was imported directly but absent from the new direct-dependency source and from the integration manifest. S01 retained all pre-existing direct requirements in `requirements-direct.txt` and declared `async-timeout` in the manifest so Home Assistant 2026.7.4 can load the integration.
- HACS action's current reviewed commit is signed and dated 2026-06-08, while its latest release tag is still `22.5.0` from 2022. The workflow pins the current commit SHA and records branch/date; S15 retains responsibility for the full action/container supply-chain audit.
- The pinned HACS action commit still declares `docker://ghcr.io/hacs/action:main` internally. S15 now explicitly requires inspection and immutable handling of nested action/image references.
- Ruff replaces the legacy flake8-style toolchain under decision D007. The broader `E`, `F`, `I`, `UP`, `B`, and `ASYNC` selection exposed import, modernization, and bugbear findings; safe automatic fixes plus two manual cleanups resolved them without changing runtime behavior.
